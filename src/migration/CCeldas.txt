PROPÓSITO
---------
Contenedor de cuadrícula 2D del motor de planos (plotting engine) de Smallworld.
Gestiona una colección ordenada de objetos c_celda (celdas individuales) dispuestos
en una matriz de N renglones × M columnas.

El acceso a cada celda se realiza mediante su posición (ren, col) que se convierte
a un índice lineal 1-based con la fórmula:
    pos = nNumCol × (ren − 1) + col

Esta fórmula es la clave de la hash_table interna en Magik y se preserva
exactamente en el Map<number, CCelda> de TypeScript.


SLOTS MIGRADOS (estado interno)
---------------------------------
  nNumRen    → _nNumRen: number        Número de renglones de la cuadrícula
  nNumCol    → _nNumCol: number        Número de columnas de la cuadrícula
  collCeldas → _collCeldas: Map<number, CCelda>
                                       Colección de celdas indexada por pos lineal
                                       Equivale a hash_table.new() en Magik.

  Los tres slots son :writable, :private en Magik → campos private en TypeScript,
  expuestos solo mediante getters/setters con validación.

FÓRMULA DE ÍNDICE LINEAL
--------------------------
La fórmula pos = nNumCol × (ren − 1) + col es la conversión de coordenadas 2D
(1-based) a índice lineal 1-based, equivalente al addressing de arrays C-style
pero con base 1 en lugar de 0.

Ejemplos para una cuadrícula 3×4 (3 filas, 4 cols):
  celda(1,1) → pos = 4×0+1 = 1
  celda(1,4) → pos = 4×0+4 = 4
  celda(2,1) → pos = 4×1+1 = 5
  celda(3,4) → pos = 4×2+4 = 12   (última celda)

Esta fórmula se preserva exactamente en TypeScript y se visualiza en la UI
con el número [n] dentro de cada celda del grid.


CCELDAS vs. CCELDA
-------------------
c_celdas (este fichero) es el CONTENEDOR de la cuadrícula.
c_celda  (fichero separado, no migrado aquí) es la CELDA INDIVIDUAL.

En esta migración se incluye un stub mínimo de CCelda con { ren, col, texto }
para que CCeldas pueda instanciar las celdas sin depender de otro fichero.
Cuando c_celda.magik sea migrado, el import se sustituirá por la clase real.


MAPEO MAGIK → TYPESCRIPT
--------------------------
  def_slotted_exemplar          → class CCeldas
  define_slot_access(:writable, :private) → campo private + getter public
  hash_table.new()              → new Map<number, CCelda>()
  hash_table[pos]               → map.get(pos) / map.set(pos, ...)
  rope.new_with(...)            → array literal [...]
  property_list.new()           → {} (Record<string, unknown>)
  .fast_keys_and_elements()     → Object.entries() / Array.forEach con índice
  _for ren _over range(1,N)     → for (let ren = 1; ren <= N; ren++)
  _try _with _when does_not_understand → try/catch (error silenciado)
  perform_private(key.with_chevron, value) → asignación directa de campo privado
  condition.raise(:warning, :string, msg) → throw new RangeError(msg)
  _return _clone                → new CCeldas(...) / return this
  >> :slotted                   → return 'slotted' as const


DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· c_celda (clase hijo individual) no está migrada en este fichero. Se incluye
  un stub CCelda con ren, col, texto. Al migrar c_celda.magik, se actualizará
  el import.

· init_with() usa perform_private(key.with_chevron, value) — en Magik esto
  invoca el setter privado del slot por nombre dinámico. En TS se mapea
  directamente con if (props.key !== undefined) ya que los slots son conocidos.

· new_from_serial() devuelve _clone (nueva instancia) en Magik. En TS se crea
  new CCeldas(nNumRen, nNumCol) explícitamente antes de llamar initWith().

· serial_structure() es un method de instancia en Magik; en TS se convierte
  en método estático ya que no depende del estado de la instancia.

· linearIndex() no existe en Magik como método público — la fórmula se usa
  inline dentro de new() y celda(). Se expone como método público en TS para
  facilitar la inspección desde la UI.
