DESCRIPCIÓN GENERAL
-------------------
Sello de layout "Resumen de materiales" para planos de red telefónica de
pares de cobre. En Magik hereda de :layout_element mediante def_slotted_exemplar.
En TypeScript se modela como clase CDtoPronostico + componente React CDtoPronosticoUI.

El sello compone 3 sub-tablas apiladas verticalmente en el layout del plano:
  tbl_Titulo       → 2f × 2c  — DTO / D.A.O.C.   (etiquetas + captura)
  tbl_pares        → 3f × 2c  — pares de cobre    (etiquetas + captura editable)
  tbl_pronosticos  → 3f × 3c  — N / N+1 / SAT.   (etiquetas + 2 cols captura vacía)
Dimensiones totales: ~33 mm alto × 33 mm ancho (escala px × 5 en la UI).


SLOTS MIGRADOS
--------------
Magik slot         → TypeScript (campo de clase)
──────────────────────────────────────────────────────────────
:oTablas           → oTablas: DtoTablas | null
:oCoordOrigen      → oCoordOrigen: { x: number; y: number }
:oWindow           → no implementado (no aplica en HTML/React)
:bTablas_Creadas   → bTablas_creadas: boolean


MÉTODOS MIGRADOS Y SU EQUIVALENCIA
------------------------------------

1. inicializa(_optional RoCoord)
   Magik: set_fill_colour(_unset) + c_tablas.new(_self) + prvCrea_Cfg_Tablas()
          + bounds = area_total() + prvLlena_Celdas_de_tablas() + bTablas_creadas=true
   TypeScript: inicializa(coord?) → _prvCreaCfgTablas() + _prvLlenaCeldasDeTablas()
   set_fill_colour → no aplica en HTML
   c_tablas.new    → inicialización de oTablas inline en _prvCreaCfgTblTitulo()
   bounds          → no aplica en HTML (el tamaño lo controla el CSS)

2. draw_content_on(window)
   Magik: if bTablas_Creadas = false → inicializa + Agrega_LYM + send_to_back
          oTablas.Despliega(window)
   TypeScript: drawContentOn() → guard if(!bTablas_creadas) → inicializa()
   La inicialización lazy se reproduce: si el sello ya fue creado, drawContentOn()
   solo retorna las tablas existentes sin recrearlas.
   El botón "drawContentOn() (guard ON)" en la UI indica cuando el guard está activo.

3. prvCrea_Cfg_Tablas()  [private]
   Magik: apila 3 tablas con coordenadas acumuladas:
     titulo     → en oCoordOrigen              (LnAltura=10)
     pares      → coordinate.new(x, y-10)      (LnAltura=9)
     pronosticos→ coordinate.new(x, y-10-9)    (LnAltura=9)
   TypeScript: _prvCreaCfgTablas() — mismo cálculo de offsets:
     const coordPares       = { x, y: y - alturaTitulo }
     const coordPronosticos = { x, y: coordPares.y - alturaPares }

4. prvCreaCfgTbl_titulo(RoCoord)  [private]
   Magik: crea_tabla(2, 2, :tbl_Titulo)
     bDibuja_bordes? = false, bDibuja_Columnas_Internas? = false,
     bDibuja_Renglones_Internos? = false
     Renglones: [5, 5] mm   Columnas: [10, 23] mm
     Celda(1,2).bordes_celda.bBorde_inf? = true → borde inferior especial
   TypeScript: _prvCreaCfgTblTitulo() → DtoSubTabla con bordeInfCeldas = Set(['0,1'])
   El borde inferior especial se renderiza en morado (#cba6f7) en la UI.

5. prvCreaCfgTbl_Pares(RoCoord)  [private]
   Magik: crea_tabla(3, 2, :tbl_pares)
     bDibuja_bordes? = true, bDibuja_Columnas_Internas? = false,
     bDibuja_Renglones_Internos? = true
     Renglones: [3, 3, 3] mm   Columnas: [15, 18] mm
   TypeScript: _prvCreaCfgTblPares() → bordesDibujados=true, rengsInternosDibujados=true

6. prvCreaCfgTbl_pronostico(RoCoord)  [private]
   Magik: crea_tabla(3, 3, :tbl_pronosticos)
     Los 3 flags bDibuja_* están comentados → todos los bordes ON por defecto
     Renglones: [3, 3, 3] mm   Columnas: [7, 8, 18] mm
   TypeScript: _prvCreaCfgTblPronostico() → tous les bordesDibujados=true
   Nota: el Magik deja los 3 flags comentados expresamente — se interpretan
   como bordes activos porque el objeto crea_tabla tiene bordes ON por defecto.

7. prvLlenaTbl_titulo()
   Magik: c_texto_grafico.new("DTO.") + c_texto_grafico.new("D.A O.C.") → col 1
          c_Captura_Texto.new("LJC-1") + .new_from(base,"538.3 MTS") → col 2
   TypeScript: textoGrafico("DTO.", 26) + capturaTexto("LJC-1", 4)
   c_texto_grafico → DtoCelda tipo='texto_grafico' (span de solo lectura)
   c_Captura_Texto → DtoCelda tipo='captura_texto' (input editable)

8. prvLlenaTbl_pares()
   Magik: c_texto_grafico "P.PRINC."/"P.SEC"/"ABNS. EXIST." + captura "300+200"/"230+380"/"166"
   TypeScript: mismo contenido; new_from(base) se traduce como textoGrafico(texto, n, base)

9. prvLlenaTbl_pronostico()
   Magik: c_texto_grafico "N"/"N+1"/"SAT." → col 1
          c_Captura_Texto vacío ×3         → col 2  (new / new_from misma base)
          c_Captura_Texto vacío ×3         → col 3  (new / new_from misma base)
   TypeScript: capturaTexto('', 2) × 6 para cols 2 y 3
   Las celdas vacías representan los pronósticos pendientes de captura.

10. Agrega_LYM(RoLym)
    Magik: oTablas.Agrega_LYM(lym) → añade todos los layout elements a la página
    TypeScript: stub agregarLYM(_lym) — no tiene equivalente en React/HTML.
    En Smallworld esto registra el sello en el layout manager para que sea
    renderizado en el canvas del plano. En HTML el render lo hace React directamente.


TIPOS DE CELDA
--------------
c_texto_grafico  → tipo='texto_grafico' → <span> de solo lectura
                   Fondo oscuro, texto blanco, negrita si tamaño ≥ 18pt.

c_Captura_Texto  → tipo='captura_texto' → <input type="text"> editable
                   Borde punteado verde, texto verde, fondo transparente.
                   Los cambios se propagan al estado React (controlado con value=).


INICIALIZACIÓN LAZY — GUARD bTablas_creadas
-------------------------------------------
Patrón Magik: draw_content_on solo inicializa si bTablas_Creadas = false.
              Si ya está creado, solo llama Despliega(window).
TypeScript: drawContentOn() reproduce el guard:
  if (!this.bTablas_creadas) { this.inicializa(this.oCoordOrigen); }
La UI muestra "(guard ON)" cuando el flag es true para hacer visible este comportamiento.


LO QUE NO SE HA MIGRADO
------------------------
- :oWindow (canvas de Smallworld) → no aplica en HTML; el render lo hace React.
- set_fill_colour(_unset) → transparencia de fondo del sello — reproducida
  con background: 'transparent' en el contenedor CSS.
- send_to_back() → orden Z en el layout — no aplica en HTML lineal.
- oTablas.Despliega(window) → renderizado en canvas GIS — sustituido por
  el árbol de componentes React.
- Agrega_LYM → ver punto 10.


DEPENDENCIAS EXTERNAS
---------------------
- React (useState, useCallback)
- Sin Turf.js ni OpenLayers: no hay geometría espacial en este componente.
