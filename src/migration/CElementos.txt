PROPÓSITO
---------
Contenedor de elementos gráficos del motor de plotting (layout / sellos) de
Smallworld. Mantiene una colección ordenada de objetos c_elemento_grafico
indexados por nombre (string → elemento), junto con la ventana (canvas) sobre
la que se dibuja y el área (bounding_box) que ocupa el contenedor.

Es la pieza intermedia entre la celda del layout (c_celda / c_celdas) y los
elementos gráficos finales (líneas, textos, símbolos). Su responsabilidad:

  1. Registrar elementos con un nombre → Agregar_elemento(...)
  2. Recuperar elementos por nombre   → obten_elemento(...)
  3. Cuando se le pide Despliega():
       · Propaga oVentana y oArea a cada hijo
       · Llama Actualiza_Area_Elemento() para que el hijo recalcule su geom
       · Llama Despliega() de cada hijo para que se dibuje en oVentana
  4. Serialización slotted (init_with / new_from_serial / serial_slots)


SLOTS MIGRADOS (estado interno)
---------------------------------
  nTotal_Elementos → _nTotal_Elementos: number
                     Contador acumulado de elementos agregados.

  collElementos    → _collElementos: Map<string, IElementoGrafico>
                     hash_table.new() en Magik → new Map<string, ...>().
                     Clave: nombre del elemento. Valor: el c_elemento_grafico.

  oVentana         → _oVentana: VectorSource | undefined
                     Canvas/superficie donde se dibuja.
                     En el sw_gis original es un "window"/canvas; aquí se
                     mapea a ol/source/Vector (OpenLayers v10).

  oArea            → _oArea: BBox | undefined        (:writable :private)
                     bounding_box en Magik → [minX, minY, maxX, maxY] en Turf.
                     Encapsulado: getter/setter dedicado (setOArea).


MÉTODOS MIGRADOS (12)
---------------------

1. constructor()
   Magik: new()
   Inicializa nTotal_Elementos a 0 y collElementos a new Map().
   _return _clone → new CElementos() en TypeScript.

2. Agregar_elemento(RoElemento, RsNombre)
   Magik:
       _self.collElementos[RsNombre] << RoElemento
       _self.nTotal_Elementos << _self.nTotal_Elementos + 1
   Inserta el elemento en el Map por nombre e incrementa el contador.

3. obten_elemento(RsNombre)
   Magik: >> _self.collElementos[RsNombre]
   Devuelve el elemento del Map (o undefined si no existe).

4. Despliega()  → async
   Magik:
       _for LoElemento _over _self.collElementos.fast_elements()
       _loop
           LoElemento.oVentana << _self.oVentana
           LoElemento.oArea    << _self.oArea
           LoElemento.Actualiza_Area_Elemento()
           LoElemento.Despliega()
       _endloop
   Itera la colección, propaga ventana y área a cada hijo y dispara su
   actualización + dibujado. Asíncrono porque cada Despliega() del hijo
   puede ser sync o devolver Promise (renderizado, fetch a servicio GIS).

5. get / set nTotal_Elementos
   Magik:
       _method c_elementos.nTotal_Elementos  → getter
       _method c_elementos.nTotal_elementos << valor  → setter
   Acceso libre al contador.

6. get / set collElementos
   Magik:
       define_slot_access(:collElementos, :writable)
       _method c_elementos.collElementos << valor
   Lectura del Map y reemplazo completo.

7. get / set oVentana
   Magik:
       define_slot_access(:oVentana, :writable)
       _method c_elementos.oVentana << RoVentana
   Recibe el canvas/VectorSource sobre el que se va a dibujar.

8. setOArea(area)  /  protected get oArea()
   Magik:
       define_slot_access(:oArea, :writable, :private)
       _method c_elementos.oArea << RoArea
   El slot es :private en Magik (solo accesible desde _self). En TS se expone
   un setter dedicado (setOArea) y un getter protected, manteniendo el
   contrato de encapsulación.

9. initWith(props)
   Magik: init_with(props)
       _for key, value _over props.fast_keys_and_elements()
       _loop
           _try _with cond
                _self.perform_private(key.with_chevron, value)
           _when does_not_understand
           _endtry
       _endloop
       _return _self
   Asignación dinámica por nombre de slot. perform_private +
   does_not_understand → en TS se mapea con if (props.key !== undefined)
   por cada slot conocido. Keys desconocidos se ignoran silenciosamente.
   Devuelve this (método fluent, como Magik retorna _self).

10. static fromSerial(keys, xmlValues)
    Magik: new_from_serial(keys, xml_values)
        props << property_list.new()
        _for nr, key _over keys.fast_keys_and_elements()
        _loop
            props[key] << xml_values[nr]
        _endloop
        _return _clone.init_with(props)
    Empareja keys[i] ↔ xmlValues[i] en un Record y construye una instancia
    nueva con initWith. Equivale a la deserialización XML del layout.

11. serialSlots()
    Magik: serial_slots()
        keys   << rope.new_with(:nTotal_Elementos, :collElementos, :oArea)
        values << rope.new_with(.nTotal_Elementos, .collElementos, .oArea)
        _return keys, values
    Devuelve { keys, values } como dos arrays paralelos.
    NOTA: oVentana NO se serializa (es estado transitorio del runtime, igual
    que en Magik — solo se serializan los 3 slots indicados).

12. static serialStructure()
    Magik: serial_structure → >> :slotted
    Indica el tipo de estructura de serialización: 'slotted'.


MÉTODOS AÑADIDOS (no en magik original — utilidades de visualización)
----------------------------------------------------------------------

· oAreaAsPolygon(): Feature<Polygon> | null
    Convierte _oArea a un GeoJSON Polygon vía turf.bboxPolygon(...).
    Permite ver el área en herramientas que consumen GeoJSON puro.

· drawOAreaToCanvas(): void
    Añade un ol/Feature con la geometría rectangular de _oArea al
    VectorSource (oVentana). Útil para depuración visual del área asignada
    al contenedor antes de dibujar los hijos.


TIPOS EXPORTADOS
-----------------
  BBox                   = [number, number, number, number]
                           Equivalente a Magik bounding_box → bbox Turf
  OlCanvas               = VectorSource (alias del canvas OL v10)
  IElementoGrafico       Contrato que deben cumplir los hijos (oVentana,
                         oArea, Actualiza_Area_Elemento, Despliega).
                         Cuando se migre c_elemento_grafico, esa clase
                         implementará IElementoGrafico.
  DemoElementoGrafico    Stub mínimo para que la UI de prueba funcione.
                         Tendrá que ser sustituido por las clases reales
                         (c_linea_grafico, c_texto_grafico, c_simbolo_grafico).
  CElementosSerialData   Tipo de los props de initWith/fromSerial.


MAPEO MAGIK → TYPESCRIPT
--------------------------
  def_slotted_exemplar          → class CElementos
  define_slot_access(:writable) → campo private + getter/setter public
  define_slot_access(:writable, :private) → campo private + setOArea / protected get
  hash_table.new()              → new Map<string, IElementoGrafico>()
  hash_table[k] << v            → map.set(k, v)
  rope.new_with(...)            → array literal [...]
  property_list.new()           → {} (Record<string, unknown>)
  .fast_keys_and_elements()     → forEach con índice / Object.entries()
  .fast_elements()              → Map.values()
  bounding_box                  → BBox [minX, minY, maxX, maxY] (turf-compatible)
  sw_gis "window" / canvas      → ol/source/Vector (OpenLayers v10)
  _self.perform_private(k<<, v) → asignación directa del campo (TS sabe los slots)
  _try / _when does_not_understand → asignación condicional (key !== undefined)
  _return _clone                → new CElementos() + initWith()
  >> :slotted                   → return 'slotted' as const


LÓGICA ESPACIAL: TURF.JS + OPENLAYERS
---------------------------------------
La clase original no realiza cálculos geométricos en sí — es orquestadora.
La sustancia espacial vive en los hijos (c_linea_grafico, c_texto_grafico,
c_simbolo_grafico, etc.). Sin embargo, esta migración expone dos puentes
para el ecosistema moderno:

· Turf.js: oAreaAsPolygon() convierte bbox → GeoJSON Polygon, que es el
  formato canónico para análisis espacial (turf.intersect, turf.buffer,
  turf.booleanIntersects). Cualquier hijo migrado que necesite cálculos
  geométricos puede consumir el GeoJSON desde aquí.

· OpenLayers v10: oVentana se modela como ol/source/Vector. Cada hijo
  cumplirá IElementoGrafico y, dentro de su Despliega(), creará features
  con new ol/Feature({ geometry: ... }) y las añadirá al VectorSource
  recibido en oVentana. El método drawOAreaToCanvas() del contenedor
  muestra el patrón básico: fromExtent(bbox) → ol/geom/Polygon →
  new ol/Feature(...) → vectorSource.addFeature(...).


DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· oArea es :private en Magik (solo modificable desde _self). En TS se
  encapsula con setOArea(...) y un getter protected — la intención de
  encapsulación se preserva sin perder la modificabilidad necesaria
  para que la UI de demo pueda asignarla.

· Despliega() es async en TS. En Magik es síncrono porque el runtime de
  Smallworld es single-threaded sobre canvas locales. En la web, cualquier
  Despliega() de un hijo puede involucrar fetch a servicios GIS o
  renderizado async, por lo que el contenedor await-ea cada hijo en orden.

· init_with() usa perform_private(key.with_chevron, value) — en Magik es
  reflexión por nombre de slot. En TS se mapea con if (props.key !== undefined)
  por cada slot conocido, ya que el conjunto de slots es fijo en compile-time.

· new_from_serial() devuelve _clone (nueva instancia) en Magik. En TS se
  crea new CElementos() explícitamente antes de llamar initWith().

· serial_structure() es instance method en Magik; en TS es static, ya que
  no depende del estado de la instancia.

· Se añaden oAreaAsPolygon() y drawOAreaToCanvas() — no existen en el
  magik original, son utilidades del puerto a Turf/OL para inspección y
  visualización.


VISTA INTERACTIVA EN App.tsx
-----------------------------
  · Estado del contenedor (nTotal_Elementos, tamaño collElementos, features OL)
  · Panel Agregar_elemento: input nombre + botón → registra DemoElementoGrafico
  · Panel obten_elemento: recupera elemento por nombre y lo loguea
  · Panel oArea + Despliega():
        - Input bbox (minX,minY,maxX,maxY)
        - Setea oArea, limpia canvas, dibuja bbox de oArea (drawOAreaToCanvas)
        - Llama Despliega() async → propaga a cada hijo
        - Muestra cuántas features acabaron en el ol/source/Vector y los
          vértices del GeoJSON Polygon vía turf.bboxPolygon
  · Tabla collElementos con nombre, bbox propio y flag desplegado
  · Panel serialización: ejecuta serial_slots + fromSerial y loguea el redondeo
  · Log de actividad con timestamps
