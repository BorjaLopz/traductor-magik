PROPÓSITO
---------
Clase base (factory) que orquesta la generación de planos de layout GIS para
redes de fibra óptica. Encapsula la secuencia completa de creación de un plano:

  iniciaLayout() → configura página 124 cm × 84 cm y obtiene el viewport
  addElementosComunes() → AddMarco() + AddTitulo() + AddSellos()

Los métodos generaPlano() y creaTitulo() están diseñados para ser subclaseados
(override) para producir tipos de plano específicos.


SLOTS MIGRADOS (estado interno)
---------------------------------
  oPage             → protected oPage: LayoutPage | null
                      Página activa del layout designer.
                      Privada en Magik (:private) — protected en TS
                      para permitir herencia.

  oViewMapperPlugin → protected oViewMapperPlugin: ViewMapperPlugin | null
                      Plugin de viewport del layout designer.
                      Privada en Magik (:private) — protected en TS.


MÉTODOS MIGRADOS (11 en total)
--------------------------------

1. new() / init()
   Magik: new() → _clone.init() → _return _self
   Patrón factory de Smallworld: new() crea un clon del ejemplar e invoca init().
   En TS: static create() → new CFactoryPlanos()._init().

2. iniciaLayout()
   Magik: inicia_layout()
   Navega la cadena de plugins:
     pni_application() → plugin(:layout_plugin) → start_layout_designer()
     → plugin(:layout_manager) → current_page
     → plugin(:viewport_mapper)
   Validación (CAMBIO 14/11/11 bflores):
     if LoPage.empty?.not → condition.raise(:user_error, :string,
       "El diseñador de planos ya tiene uno activo. Favor de cerrarlo...")
   Configura tamaño: set_paper_size(12400, 8400) → 124 cm × 84 cm
   Retorna tuple: (LoPage, LoViewMapperPlugin)
   En TS: devuelve { page, viewport } | { error: string }.

3. getMapView(geom?)
   Magik: GetMapView(PoGeom)
     map_plugin.current_map_view → si geom → .goto(PoGeom) → vuelve a pedir
   Patrón de centrado del mapa en una geometría específica.
   En TS: devuelve MockMapView con centeredOn = geom | null.

4. generaPlano()
   Magik: genera_plano()
     (.oPage, .oViewMapperPlugin) << _self.inicia_layout()
     _self.AddElementos_comunes()
   Orquestador principal. Diseñado para ser subclaseado.
   En TS: devuelve { ok: boolean, message: string }.

5. addElementosComunes()
   Magik: AddElementos_comunes()
     if .oPage _isnt _unset → AddMarco() → AddTitulo(marco) → AddSellos()
   Guarda el marco devuelto para pasarlo a AddTitulo (los bounds del marco
   determinan la posición del título).

6. addMarco()
   Magik: AddMarco()
     c_marco.new_with(:bounds, bounding_box.new(0,0,1,1))
     .Largo = 6 / .Alto = 3 / .set_fill_colour(_unset)
     oPage.add_element(LoMarco)
   El marco actúa como contenedor del plano. Sus bounds son el punto de
   referencia para posicionar el título.
   En TS: los bounds del mock cubren toda la página (0,0,12400,8400) para
   que el cálculo de posición del título sea coherente en la visualización.

7. addTitulo(marco)
   Magik: AddTitulo(PoMarco)
     LoBB = bb(marco.xmax-2200, marco.ymin+200, marco.xmax-200, marco.ymin+600)
     c_titulo_de_plano.new_with(:bounds, LoBB, :font_name,"bold", :font_size,8,
       :fill_style,_unset, :outline_style,_unset, :text, creaTitulo(),
       :wrap,_false, :align_horizontal,:centre, :align_vertical,:centre,
       :orientation,:left_right)
   El título se posiciona en la esquina superior derecha del marco:
     x: [xmax-2200, xmax-200] — ancho de 2000 unidades
     y: [ymin+200,  ymin+600] — altura de 400 unidades
   En el mock (marco 12400×8400): título en (10200,200,12200,600).

8. addSellos()
   Magik: AddSellos()
   Añade 3 elementos:
     c_sello_ruta_cables_fo   → bb(450, 400, 2100, 3000)  — sello directo
     c_sello_estandar_base_fo → bb(285, 400, 2100, 3000)  — via c_generador_sellos
     c_notas_constructor      → bb(450, 400, 2100, 5000)  — via c_generador_sellos
   c_generador_sellos.obten_instancia() es el patrón singleton para la
   generación de sellos estándar. En TS: integrado directamente en addSellos().

9. creaTitulo()
   Magik: crea_titulo → _return "Titulo"
   Método base que devuelve la cadena del título del plano.
   Pensado para ser subclaseado en cada tipo de plano específico.
   En TS: devuelve "Titulo" como implementación base.

10. asignaPaginaYViewport(page, viewport)
    Magik: asigna_pagina_y_viewport(Popagina, Poviewport)
    Permite asignar externamente la página y el viewport desde otra clase.
    Diseñado para desacoplar la creación del layout de la generación del plano.

11. reset() / getPage() / getViewport()
    Métodos auxiliares añadidos en TS para facilitar el control del ciclo
    de vida en la UI (sin equivalente directo en Magik).


PÁGINA Y COORDENADAS
---------------------
set_paper_size(12400, 8400) → 124 cm de ancho × 84 cm de alto
  (unidades: 1/100 mm → 12400/100 = 124 cm, 8400/100 = 84 cm)

Coordenadas de los sellos (esquina inferior-izquierda del plano):
  c_sello_ruta_cables_fo:   x=450-2100  (17.65mm), y=400-3000  (24cm)
  c_sello_estandar_base_fo: x=285-2100  (14.85mm), y=400-3000  (24cm)
  c_notas_constructor:      x=450-2100  (17.65mm), y=400-5000  (40cm)

Título (relativo al marco de página completa):
  x=10200-12200  (esquina derecha), y=200-600 (franja superior)


VALIDACIÓN iniciaLayout()
---------------------------
Cambio introducido el 14/11/11 (bflores):
  Si la página ya tiene contenido (LoPage.empty?.not) → error de usuario:
  "El diseñador de planos ya tiene uno activo. Favor de cerrarlo..."
En TS: if (this.oPage !== null && elements.length > 0) → { error: string }
Esta validación impide generar planos duplicados sin cerrar el anterior.


PATRÓN DE SUBCLASIFICACIÓN
----------------------------
El diseño original prevé herencia en dos puntos:
  · generaPlano()  — override para añadir elementos extra al plano
  · creaTitulo()   — override para devolver el título específico de cada plano

Ejemplo de subclase:
  class CFactoryPlanosRuta extends CFactoryPlanos {
    creaTitulo(): string { return 'PLANO DE RUTA DE CABLES FO'; }
    generaPlano() {
      super.generaPlano();
      this.addElementosEspecificos();
    }
  }

DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· Sin clase padre explícita en Magik → clase TypeScript base sin extends.

· _clone.init() → patrón estático create() + constructor privado. En TS no hay
  "_clone" real; se instancia directamente con new.

· La cadena de plugins (layout_plugin → layout_designer → layout_manager →
  viewport_mapper) se mockea con funciones makePage() y makeViewport().

· c_marco con Largo=6/Alto=3 → en el mock los bounds del marco cubren toda la
  página (0,0,12400,8400) para que el cálculo de posición del título sea correcto.

· c_generador_sellos.obten_instancia() (patrón singleton) → en TS los sellos
  se crean directamente en addSellos() sin instancia separada.

· El visualizador SVG muestra la página de layout escalada con flip-Y
  (Smallworld usa y↑; SVG usa y↓).

· El componente UI añade:
  - Visualización SVG de la página 124cm × 84cm con los elementos en su posición
  - Tabla de elementos con bounds y metadatos
  - Manejo del error "página ya activa" con feedback visual
  - Botones para todos los métodos públicos incluido asignaPaginaYViewport()
