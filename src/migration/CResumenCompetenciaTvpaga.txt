PROPÓSITO
---------
Sello de layout GIS que genera el resumen de competidores y TV de paga
para planos de construcción de fibra óptica (red Telmex).

El sello recorre el inventario de viviendas dentro de un área óptica
y acumula 15 contadores que representan los servicios de la competencia
presentes en el territorio del plano.

Es complementario al sello principal de red secundaria: mientras ese
sello muestra la infraestructura Telmex, este sello muestra la competencia
(TV satelital, cable, operadores inalámbricos, fibra de competidores, etc.).


SLOT MIGRADO
-------------
  oDtoOptico → oDtoOptico: instancia del DTO óptico del área de trabajo.
    Contiene el campo user!_limite (polígono GIS que delimita el área).
    Se obtiene en llena_datos_celdas() desde elementos_bd_lb[1].
    En la migración TS se parametriza como argumento de calculaDatos().


MÉTODOS MIGRADOS (4 en total)
-------------------------------

1. calcula_datos() → calculaDatos(viviendas, limite, lineasLadatel)
   ─────────────────────────────────────────────────────────────────
   Corazón de la lógica de negocio. Pasos:

   a) Inicializa 15 contadores a 0 (property_list → ValoresCompetencia).

   b) Líneas Ladatel (NOTA 11/09/12 fmejia):
      Obtiene el conteo de teléfonos públicos TPTC desde c_distrito.
      En TS se recibe como parámetro lineasLadatel (viene de c_distrito).

   c) Selección espacial de viviendas:
      Magik: LoTabVivienda.select(predicate.interacts(:location, LoPsa))
      TS:    turf.booleanPointInPolygon(vivienda.location, limite)
      OL:    ol/VectorSource.getFeaturesAtCoordinate / ol/extent.intersects
      Solo viviendas cuyo punto (location) cae dentro del polígono límite.

   d) Iteración del inventario:
      Para cada vivienda dentro del límite, itera user!_inventario_viviendas.
      Acumula por servicio + producto/tipo_servicio/empresa:

      TELEFONO:
        LINEAS INALAMBRICAS             → lineas_inalambricas
        LINEAS LADAFON                  → lineas_ladafon
        LINEAS COBRE                    → lineas_cobre
        LINEAS PSLT                     → lineas_pslt
        SOLICITUDES                     → solicitudes
        LINEAS COMPETENCIA COBRE        → lineas_competencia_cobre
        LINEAS COMPETENCIA INALAMBRICAS → lineas_competencia_inalambrica
        TELEFONO PUBLICO COMPETENCIA    → telefono_publico_competencia
        TELMEX LINEAS FIBRA             → fibra_telmex
        COMPETENCIA LINEAS FIBRA        → fibra_competencia

      TV (NOTA 12/08/10 lunal — tres _if independientes):
        tipo_servicio=SATELITAL AND empresa≠DISH → tv_satelital
        empresa=DISH                             → tv_dish
        tipo_servicio=CABLE                      → tv_cable
        producto=TELMEX LINEAS FIBRA             → fibra_telmex  (_elif)
        producto=COMPETENCIA LINEAS FIBRA        → fibra_competencia (_elif)
        IMPORTANTE: tv_* y fibra_* son _if separados — un item TV puede
        incrementar tv_satelital Y fibra_telmex al mismo tiempo.

      INTERNET:
        INFINITUM                → infinitum
        TELMEX LINEAS FIBRA      → fibra_telmex
        COMPETENCIA LINEAS FIBRA → fibra_competencia

      NOTA: fibra_telmex y fibra_competencia se acumulan desde los tres
      servicios (TELEFONO, TV, INTERNET) — se suma el total de todas
      las líneas de fibra sin importar el servicio asociado.


2. configura_tabla() → constantes de tabla + renderizado HTML
   ─────────────────────────────────────────────────────────────
   Crea tres tablas apiladas verticalmente:

   tbl_titulo   (1 fila  × 1 col)  row=[6]mm,            col=[50]mm
   tbl_titulo2  (1 fila  × 3 cols) row=[6]mm,            cols=[11,9,30]mm
   tbl_contenido (15 filas × 3 cols) rows=[6×12, 7, 6×2]mm, cols=[11,9,30]mm

   Ancho total: 50mm en las tres tablas (coherente).
   Alto total: 6+6+91 = 103mm.

   Fila 13 (PSLT) es 7mm — 1mm más alta que las demás.

   En TS: los parámetros de dimensión están en ALTURAS_MM y ANCHOS_MM.
   Factor de escala para pantalla: MM_PX = 4px/mm → 200px de ancho total.


3. etiqueta_celdas() → constante FILAS_CONTENIDO
   ─────────────────────────────────────────────────
   Define qué símbolo GIS (col 1), qué etiqueta de tipo (col 3) y qué
   clave del ValoresCompetencia (col 2) corresponde a cada fila.

   Col 1: símbolo GIS (p_tv_satelital, p_fo_telmex, etc.)
          En producción: estilos de punto del framework Smallworld.
          En UI: círculos de colores placeholder.

   Col 3: texto descriptivo del servicio (VERDE = rgb(0,76,0)).
          Fila 13 usa salto de línea: "LINEA DE TELEFONO DE TIPO\nRESIDENCIAL (PSLT)"

   Col 2: número calculado de líneas/servicios (vacío para fila 1 = PREDIO).

   MAPEO FILA → CLAVE (llena_datos_celdas):
     1  PREDIO DESHABITADO      → (vacío)
     2  TELEVISION SATELITAL    → tv_satelital
     3  TELEVISION SATELITAL (DISH) → tv_dish
     4  TELEVISION/CABLE        → tv_cable
     5  OPERTELES               → lineas_competencia_cobre
     6  INALAMBRICA OPERTELES   → lineas_competencia_inalambrica
     7  INALAMBRICA TELMEX      → lineas_inalambricas
     8  TEL/PUB COMPET.         → telefono_publico_competencia
     9  CASETA LADAFON          → lineas_ladafon
    10  CASETA LADATEL          → lineas_ladatel
    11  SOLICITUD               → solicitudes
    12  INFINITUM               → infinitum
    13  LINEA PSLT              → lineas_pslt
    14  FIBRA TELMEX            → fibra_telmex
    15  FIBRA COMPETENCIA       → fibra_competencia


4. llena_datos_celdas() → render de CResumenCompetenciaTvpagaUI
   ───────────────────────────────────────────────────────────────
   En Magik: obtiene oDtoOptico de elementos_bd_lb[1], llama calcula_datos()
   y asigna cada valor a la celda (fila, 2) de tbl_contenido.
   En TS: useMemo recalcula valores cuando cambia el límite o ladatel.


INTEGRACIÓN CON OPENLAYERS
----------------------------
La selección espacial en Magik usa pseudo_area (polígono GIS del framework).
En una app OL real:

  // Crear feature del límite
  const limiteFeature = new Feature({
    geometry: new Polygon(coords),
  });
  const vectorSource = new VectorSource({ features: [limiteFeature] });

  // Filtrar viviendas que intersectan
  const extent = limiteFeature.getGeometry()!.getExtent();
  const viviendasEnLimite = viviendasSource
    .getFeaturesInExtent(extent)
    .filter(f => limiteFeature.getGeometry()!.intersectsExtent(
      f.getGeometry()!.getExtent()
    ));

En la migración se usa Turf.js booleanPointInPolygon() que es exacto para
puntos dentro de polígonos, más eficiente que el extent check de OL.


DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· El dataset GIS (:gis) se parametriza como array de mock data.
  Nota histórica: el código original usaba :gis después de cambiar desde
  :design_admin (comentario AHERNAN/HILDEBRANDO 2012-07-05).

· c_distrito y c_proyecto se simulan con el parámetro lineasLadatel.
  En producción serían instancias de las clases del framework.

· Los atributos de Magik (.user!_servicio, .user!_producto, etc.)
  se convierten a propiedades tipadas de la interfaz InventarioVivienda.

· La UI añade:
  - Mini-mapa SVG mostrando el polígono límite y los puntos vivienda
    (verde = dentro, rojo = fuera) — equivalente visual a un VectorLayer OL.
  - Panel de valores calculados con resaltado de valores > 0.
  - Control para ajustar lineas_ladatel dinámicamente.
  - Checkbox para activar/desactivar el límite óptico.

· La fila 1 (PREDIO DESHABITADO) siempre muestra celda vacía en col 2
  porque en llena_datos_celdas() se asigna "" explícitamente, sin clave
  en ValoresCompetencia.

· lineas_cobre se calcula pero no aparece en ninguna fila del sello
  (comentario Magik 11/09/29 lgranados: "se oculta el renglón"). El slot
  existe para compatibilidad con subclases.
