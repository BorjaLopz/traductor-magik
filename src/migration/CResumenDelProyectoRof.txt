PROPÓSITO
---------
Sello/layout que muestra la "Lista de materiales (resumen del proyecto)" en
planos de Fibra Óptica. Pinta una tabla 4 columnas con:

    No | DESCRIPCION | CANTIDAD | UNIDAD MED.

El número de filas (2 + N) depende dinámicamente del contenido de
LoElemResumen, una lista de tripletas [descripción, cantidad, unidad].

El sello también define un atributo dinámico por cada descripción. Si el
usuario edita ese atributo (a través del catálogo de atributos del layout),
su valor sobrescribe la cantidad en la celda correspondiente. Esto permite
ajustar manualmente cantidades sin tocar los datos de origen.


SLOTS MIGRADOS (estado interno)
---------------------------------
  :tipo            → tipo: TipoResumen
                     'ELEM_RED' | 'ESTRUCTURAS' | undefined
                     Indica si el sello es de elementos de red o de
                     estructuras. En el Magik original es informativo
                     (no afecta la generación de la tabla).

  :LoElemResumen   → LoElemResumen: ResumenRow[]
                     Lista de tripletas [desc, cantidad, unidad_med].
                     Define dinámicamente filas de la tabla y
                     atributos dinámicos.

  Heredados de c_base_sello_fibra (simulados para la demo):
    o_color_linea  → [1.0, 0.0, 0.0]  (rojo)
    o_coord_inicio → [0, 0]
    attributes     → Record<string, AttributeDef>
    o_tablas       → { tbl_lista_materiales?: TablaResumen }

DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· c_base_sello_fibra (padre) NO está migrado. Los métodos heredados
  (asigna_texto_celda, _super.new_with, _super.defined_attributes, etc.)
  se simulan con un helper privado _asigna_texto_celda() y un array vacío.
  Cuando c_base_sello_fibra se migre, esta clase deberá extenderla y
  delegar realmente vía super.

· Dimensiones en mm (configura_tabla) se conservan como metadatos en el
  objeto TablaResumen pero no se aplican al render HTML — el componente
  React usa proporciones relativas (porcentajes) en <colgroup>.

· :centre_right (Magik) no tiene equivalente exacto en CSS text-align;
  se mapea a 'center'. Si el rendering definitivo requiere alineación
  exacta, habrá que añadir padding-right manual.

· `fill_up_with(%space, 10)` se conserva en la lógica TS para mantener
  fidelidad con el dato que llegaría al motor de plotting Magik, aunque
  en HTML los espacios trailing son colapsados por el browser. Esto NO
  rompe nada: la longitud del string sigue siendo la esperada para
  exportaciones a PDF/SVG con fuentes monoespaciadas.

· El componente UI añade:
  · Selector :tipo (ELEM_RED / ESTRUCTURAS) con datasets mock distintos
  · Botones inicializar / reset
  · Panel de override de atributos dinámicos (input por cada descripción)
  · Indicadores de slot (tipo, LoElemResumen.size, o_color_linea, dims tabla)
  · Las celdas marcadas por asigna_celdas_a_colorear() se pintan con
    el color o_color_linea (rojo) — texto, no fondo, para mantener legible.
