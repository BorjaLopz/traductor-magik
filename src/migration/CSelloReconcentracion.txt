DESCRIPCIÓN GENERAL
-------------------
Sello "TABLA DE BAJANTES" para planos de red de cobre. Muestra una matriz
de conteos de Unidades de Construcción (UCs) clasificadas por tipo de
trabajo (4 secciones) y tipo de cable (8 tipos por sección).

En Magik hereda de :c_base_sello_cobre. En TypeScript se modela como
componente React funcional con datos obtenidos de forma asíncrona
(simulando la llamada GIS + costeo).

Estructura de la tabla — tbl_reconcentracion (11 filas × 8 columnas):
  Fila  1 (10mm): Título "TABLA DE BAJANTES" — cols 1-7 sin borde derecho
  Fila  2 ( 5mm): Cabeceras de sección (Precableado/Reconcentración/Reconexión/Rehabilitación)
  Fila  3 ( 5mm): Sub-cabeceras "UC" y "Total" para cada sección
  Filas 4-11(5mm): Etiquetas de tipo en cols impares / conteos en cols pares

Dimensiones totales: 60mm alto × 104mm ancho (fila1=10 + 10×5=50; 8×13=104)

MÉTODOS MIGRADOS Y SU EQUIVALENCIA
------------------------------------

1. configura_tabla()  [private]
   Magik: crea_tabla(11, 8, :tbl_reconcentracion)
     - Row 1: nLongitud=10mm; rows 2-11: nLongitud=5mm (bucle range(2,11))
     - Cols 1-8: nLongitud=13mm (bucle range(1,8))
     - Bordes ocultos fila 1: bBorde_Der?=false para cols 1..7 (cols 1..LnColumnas-1)
     - Bordes ocultos fila 2: bBorde_Der?=false para cols impares 1,3,5,7
       (2*LnPos-1 con LnPos=1..4)
   TypeScript: función hasBorderRight(fi, ci, numCols):
     - fi=0 (fila 1): siempre false → título se ve como celda fusionada
     - fi=1, ci%2===0 (cols impares 1-based): false → sección abarca 2 cols
     - resto: true
   Constantes ROW_HEIGHTS=[10,5,5,...] y COL_WIDTH=13 reproducen nLongitud.

2. etiqueta_celdas()
   Magik: asigna c_texto_grafico a celdas con texto y tamaño fijo.
     - Celda(1,4): "TABLA DE BAJANTES", tamaño 40, margen_izq 13
     - Fila 2, cols 2*LnN-1: "Precableado"/"Reconcentración"/"Reconexión"/"Rehabilitación"
     - Fila 3, cols impares: "UC"; cols pares: "Total"
     - Filas 4-11, col 1:  CALEAE..CACLSU  (G1, 8 valores)
     - Filas 4-11, col 3:  CARSAE..CARCSU  (G2, 8 valores)
     - Filas 4-11, col 5:  CAA014/CAS014   (G3, solo 2 valores)
     - Filas 4-11, col 7:  CARLAE..DADLSU  (G4, 8 valores)
   TypeScript: función cellText(fi, ci) que devuelve el texto de cada celda
   según su posición. No hay objetos c_texto_grafico — el texto se renderiza
   directamente en la <td>.

3. llena_datos_celdas()
   Magik: construye LcollTotalUcs[4][8] acumulando cantidades por grupo:
     - Para cada UC: busca su tipo en LsvEtiquetas[1..4]
     - Si _unset → asigna; si ya existe → suma (+<<)
     - Finalmente: Celda(3+LnM, 2*LnN).oElemento = c_texto_grafico.new(LsNumero)
       donde LsNumero = LcollTotalUcs[N][M].floor.write_string
   TypeScript: función buildDataMatrix(ucs):
     - Record<"grupoIdx_rowIdx", number> con acumulación de cantidad
     - Usa indexOf sobre las constantes de etiquetas para localizar grupo+fila
     - El resultado alimenta cellText() para las celdas de datos
   Nota: la columna de datos es 2*N (1-based) = 1,3,5,7 (0-based) = cols PARES en 0-based.

4. ucs()
   Magik:
     1. swg_dsn_admin_engine.active_scheme.user!_distrito → nombre del distrito activo
     2. gis_program_manager.cached_dataset(:gis).collections[:user!_bajante]
        .select(predicate.eq(:user!_distrito, LsNom_dist))  → filtra bajantes por distrito
     3. c_administrador_costeo.new().get_elementos(bajantes) → (UCs, Faltas)
     4. LocollUcs.add_all(LocollFaltas) → une UCs y faltas
   TypeScript: función async fetchUcs(distrito):
     - Simula latencia con setTimeout (200ms)
     - Devuelve MOCK_UCS (array de UCItem con tipo y cantidad)
     - El filtrado por distrito es un parámetro de entrada (sin Turf.js —
       predicate.eq es un filtro de atributo, no espacial)
   La llamada es asíncrona y se ejecuta en useEffect al montar el componente.


LÓGICA DE BORDES — EQUIVALENCIA VISUAL
---------------------------------------
Magik usa bBorde_Der?=false para "fusionar" celdas visualmente.
TypeScript: la función hasBorderRight() reproduce exactamente los dos patrones:

  Patrón 1 — Fila 1 (título):
    Magik: _for LnPos _over range(1, LnColumnas-1) → oculta cols 1..7
    TypeScript: fi===0 → return false (todas las celdas excepto la última)
    Efecto: "TABLA DE BAJANTES" en col 4 se lee como si ocupara toda la fila.

  Patrón 2 — Fila 2 (secciones):
    Magik: _for LnPos _over range(1, LnColumnas/2) → oculta 2*LnPos-1 = 1,3,5,7
    TypeScript: fi===1 && ci%2===0 → return false
    Efecto: "Precableado" etc. visualmente abarca las 2 columnas de su sección.


DIFERENCIA G3 (Reconexión) — SOLO 2 ETIQUETAS
----------------------------------------------
LsvEtiquetas[3] = simple_vector.new_with("CAA014", "CAS014") — solo 2 items.
En llena_datos_celdas(): _if LnN <> 3 → LnColumnas=8, else → LnColumnas=2
TypeScript: SECCIONES[2].maxRows=2 y ETIQUETAS_G3 tiene 2 elementos.
Las filas 4-5 de la sección Reconexión tienen datos; filas 6-11 quedan vacías.

LO QUE NO SE HA MIGRADO
------------------------
- c_texto_grafico.nTamanio (40 para título, 20 para resto): en TypeScript se
  reproduce con CSS fontSize (10px título, 8px cuerpo). No hay mapeo directo pt→px.
- c_texto_grafico.nMargen_Izq=13: reproducido con padding CSS.
- La herencia de :c_base_sello_cobre: los campos heredados (o_tablas,
  o_coord_inicio, etc.) no se modelan — solo la lógica propia de este sello.
- draw_content_on(): no hay canvas/window — el render lo hace React directamente.
- predicate.eq(:user!_distrito, dist): filtro de atributo GIS, reproducido
  como parámetro de función (no usa Turf.js porque no es query espacial).


DEPENDENCIAS EXTERNAS
---------------------
- React (useState, useEffect)
- Sin Turf.js: el único query GIS es un filtro de atributo (predicate.eq),
  no un cálculo espacial geométrico.
- Sin OpenLayers: no hay renderizado en mapa.
