── QUÉ HACE ────────────────────────────────────────────────────────────────────

Es un elemento de layout de Smallworld que dibuja un "corte geográfico":
una vista del mapa insertada en un plano impreso, mostrando la infraestructura
de red junto a la geografía del entorno (colonias, lotes, distritos).

El corte se compone de tres partes:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  VIEWPORT (bounding_box 200,200 → 1500,1500)                           │
  │                                                                         │
  │   ══════════════════════════════ ← Ruta de arranque (azul, 3px)        │
  │                                    (.oRwoArranque.route)                │
  │   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ← Límites de colonia (landbase)        │
  │  ┌──────────┐ ┌────────────────┐ ← Lotes (user!_lote)                 │
  │  │  LOTE    │ │    LOTE        │   filtrados por buffer 500 m          │
  │  └──────────┘ └────────────────┘                                       │
  │  ╔══════════════════╗ ← Límite de distrito (user!_distrito)            │
  │  ║   DISTRITO       ║                                                  │
  │  ╚══════════════════╝                                                  │
  └─────────────────────────────────────────────────────────────────────────┘

Flujo principal:
  1. Dibuja_Calles? = "Si" → draw_content_on() → Dibuja_Corte()
  2. Dibuja_Corte() crea viewport, mapea la vista actual del mapa
  3. Dibuja la ruta de arranque en azul
  4. Para cada capa (colonia / lote / distrito): carga features del dataset
     landbase y dibuja solo los que intersectan el buffer de 500m de la ruta

Equivalencias tecnológicas:
  Viewport del Layout Designer → OL Map + View
  bounding_box.new(200,200,1500,1500) → dimensiones del div OL (en CSS)
  dibuja_geometria_en_viewport()      → OlFeature + VectorSource.addFeature()
  dibuja_contenido_en_buffer()        → turf.buffer() + turf.booleanDisjoint()

  Es el método central. Equivalencia bloque a bloque:

  Paso  Magik                                            TypeScript
  ────  ───────────────────────────────────────────────  ────────────────────────────────
  1     LoVpBound << bounding_box.new(200,200,1500,1500)  Dimensiones del div OL (CSS px)
        LoViewport << viewport_layout.new_with(:bounds)   new OlMap({ target: mapDiv, ... })
        LoViewport.set_fill_colour(_unset)                 sin fondo CSS específico

        LoViewport.name << "Viewport 1"

  3     dibuja_geometria_en_viewport(window,               OlFeature con estilo azul 3px
          .oRwoArranque, vpName, _unset,                   → routeSource.addFeature()
          _true, :route, :linea, :blue, 3, ...)

  4     LoLista_Geometrias << { c_Tipo_Geom.new(...) × 3 } const LISTA_GEOMETRIAS: TipoGeomItem[]

  5     _for LoRegistro _over LoLista_Geometrias.elements() for (const item of LISTA_GEOMETRIAS)

        LdscTabla  << LoRegistro.perform(:oTabla)           item.tabla
        LdsrCampoG << LoRegistro.perform(:oTipo_geom)       item.campoGeom

  6     dibuja_contenido_en_buffer(window, vpName,          turf.buffer(ruta, 0.5km)
          .oRwoArranque.route, _true, 500000,               turf.booleanDisjoint → filtro
          LdsDataSet, LdscTabla, LdsrCampoG, :linea)        VectorSource.addFeature()

  DETALLE del buffer (paso 6):
    Magik: 500000 = 500 000 unidades de mapa del sistema nativo Smallworld.
    En proyecciones típicas (metros), esto equivale a 500 km, lo cual no tiene
    sentido para un corte urbano. Se interpreta como milímetros de mapa → 500 m.
    En Turf.js: turf.buffer(ruta, 0.5, { units: 'kilometers' }) → 500 m.

  Implementación del filtro "dibuja_contenido_en_buffer":
    Magik encapsula la lógica en el método del mixin (no visible en este fichero).
    Su semántica es: "dibuja solo los objetos que intersectan el buffer de la ruta".
    En TS: turf.booleanDisjoint(feat, bufferZone) → si disjoint, se descarta.
    El wrapper try/catch protege de geometrías inválidas en los datos de prueba.

  LoLista_Geometrias (las 3 capas del landbase):

── LO QUE NO SE TRANSCRIBIÓ ────────────────────────────────────────────────────

- Herencia múltiple de mixins Smallworld:
  {:layout_element, :layout_element_mixin, :viewport_layout_mixin}
  → Estos mixins dan acceso a: layout_page, viewports, connect_to_first_viewport_on_page,
    dibuja_geometria_en_viewport, dibuja_contenido_en_buffer, etc.
  → En TS: la lógica de estos métodos se implementa directamente en dibujaCorte()
    usando Turf.js y OL, sin necesitar la cadena de herencia.

- depends_on?(another)
  → Delega al mixin viewport_layout_mixin para gestión de dependencias entre
    layout elements. Sin equivalente en TS (es infraestructura del framework SW).

- initialise_for_page(a_layout_page)
  → connect_to_first_viewport_on_page() es infraestructura del Layout Designer.
  → En TS: el OL Map se inicializa en el useEffect del componente React.

- _pragma(classify_level=restricted)
  → Metadatos del sistema de clasificación de Smallworld. Sin equivalente TS.

- smallworld_product.pni_application()
  → Referencia singleton a la aplicación PNI. En TS no se necesita; el acceso
    al mapa se hace a través del OlMap instanciado en el componente React.

- LoViewport.name << "Viewport 1"
  → Nombre para identificar el viewport dentro del layout_page. En OL el mapa
    está referenciado directamente por el ref del componente React (olMapRef).

- LoMapView.map.ace_name << "OCULTOS"
  → Cambia el ACE (Attribute Colour Entry) del mapa activo a "OCULTOS" para
    ocultar determinadas capas durante el renderizado del corte. Es una
    operación interna del motor de renderizado de Smallworld. Sin equivalente
    directo en OL (las capas se gestiona con layer.setVisible() en OL).

- vp << _self.viewports.an_element()
  → Acceso al primer viewport disponible desde el mixin. En OL se usa
    directamente olMapRef.current.

── FLUJO DE USO ────────────────────────────────────────────────────────────────

  // Solo lógica (sin UI):
  const routeSource   = new VectorSource();
  const layerSources  = {
    'colonia':         new VectorSource(),
    'user!_lote':      new VectorSource(),
    'user!_distrito':  new VectorSource(),
  };

  const corte = new CCorteGeografico();
  corte.setDibujaCalles('Si');

  const result = await corte.drawContentOn(routeSource, layerSources, service);
  // result → { featuresDrawn: N }
  // routeSource       → 1 OlFeature (línea azul, 3px)
  // layerSources['colonia']       → features dentro del buffer
  // layerSources['user!_lote']    → features dentro del buffer
  // layerSources['user!_distrito'] → features dentro del buffer

  // Con Dibuja_Calles? = "No":
  corte.setDibujaCalles('No');
  const result2 = await corte.drawContentOn(...);
  // result2 → null (draw_content_on no ejecuta Dibuja_Corte)

  // Componente demo React:
  <CorteGeograficoUI />
  // → Selector Dibuja_Calles? (Si/No)
  //   Botón "Dibujar Corte" → ejecuta drawContentOn()
  //   Mapa OL con ruta azul y capas landbase coloreadas por tipo
  //   Zoom automático al extent de la ruta tras dibujar
  //   Leyenda de capas con colores y campos geométricos
  //   Contador de features dibujados dentro del buffer
