PROPÓSITO
---------
Clase BASE de todos los elementos GIS de plano (layout) en Smallworld PNI.
Define los atributos compartidos y los métodos de utilidad comunes que
heredan todas las subclases (c_norte, c_sello_*, c_placa_*, etc.).

Responsabilidades principales:
  1. Declarar atributos comunes (estilo, lock, refs a BD, cedos)
  2. Serializar/deserializar referencias a elementos de BD GIS y Landbase
  3. Transformar coordenadas entre sistemas (GIS, canvas, viewport/página)
  4. Construir indicadores de posición: líneas que señalan un objeto GIS
     desde el plano hacia un símbolo de estilo

En TS es implementada como clase base (LayoutElement) exportable que
las demás clases migradas pueden extender o componer.

TIPOS TypeScript
-----------------
  ElementRef = Record<string, number>
    Un par {collectionName: id} por elemento.
    Magik: property_list con un solo key=collection, value=id.

  GisRecord
    id, sourceCollection, location {x,y}, label?
    Reemplaza el objeto DB de Smallworld (obj.source_collection.name, obj.id)

  AffineTransform { scaleX, scaleY, tx, ty }
    Versión simplificada de la transformación 3×3 de Smallworld.
    viewport.transform en Magik convierte coordenadas GIS → página.

  LayoutViewport { bounds: BBox, transform: AffineTransform }
    Encapsula RoViewport del Magik original.

  IndicadorResult
    coordVp, coordP2, styleBox, derecho, conPuntaActivo, usaViewportActivo

4. obtener_elementos_bd_gis()
   → obtenerElementosBdGis(dataset): GisRecord[]

7. TransformaCoordenada(PoAreaDibujo, PoCoordenada, PfEscala, PoSegTransformacion)
   → transformaCoordenada(isCanvas, coord, escala, segTransform?): Pt
   ─────────────────────────────────────────────────────────────────────
   Transforma una coordenada GIS a coordenadas de página/layout.

   Dos caminos según tipo de destino:

   a) Canvas (isCanvas = true):
      Se activa cuando el plano se exporta a impresora/plotter/SVG/PDF.
      Aplica primero: coord = coord × escala (por defecto 0.1 = 1/10)
      Magik: PoCoordenada.transformed(transform.new().scalexy(e, e))

   b) Viewport/pantalla (isCanvas = false):
      No aplica la escala previa. La coordenada pasa directamente a la
      segunda transformación.

   En ambos casos: si segTransform está definido, aplica la transformación
   afín del viewport (GIS → coordenadas de página de Layout Designer).

   NOTA: El código tiene una sección comentada (#) que verifica si la
   coordenada resultante cae dentro del bounds de la página. Se omite
   en la migración TS porque no tiene efecto (solo write).


8. indicadores(PoAreaDibujo, PoRegistro, PyCampoGeom, RoViewport, ...)
   → calcIndicador(params: IndicadorParams): IndicadorResult
   ──────────────────────────────────────────────────────────
   Crea un elemento c_style_y_viewport_layout en el plano que muestra
   una línea indicadora desde un objeto GIS hacia un símbolo de estilo.

   Pipeline:
   a) Obtiene coord GIS del registro: registro.location (= registro.perform(campo).coord)
   b) Transforma coord GIS → página: transformaCoordenada(false, coord, 0.1, vp.transform)
   c) Calcula endpoint del indicador:
      · conLinea=true + lineaAbajo=true  → (vp.xmin+distXP, vp.ymin−distYP)
      · conLinea=true + lineaAbajo=false → (vp.xmin+distXP, vp.ymax+distYP)
      · conLinea=false                   → misma coordenada del punto GIS
   d) Crea style box centrado en el endpoint:
      bounding_box.new(0,0,ancho,alto).centre = coordP2
   e) Configura flags del c_style_y_viewport_layout:
      · derecho = (coordP2.x >= coordVp.x)
      · con_punta, usa_viewport, con_linea, derecho
   f) Llama crea_figura con PaDiseno (3-8 args, dispatch por tamaño)
   g) Agrega el elemento a la página: layout_document.current_page.add_element(LoDibujo)
      En TS: retorna IndicadorResult en lugar de mutar la página.

   BUG DOCUMENTADO EN MAGIK ORIGINAL:
   ─────────────────────────────────
   Las líneas al final del método sobreescriben siempre:
     LoDibujo.con_punta << "No"   ← sobreescribe el bloque if/else anterior
     LoDibujo.usa_viewport << "Si" ← sobreescribe el bloque if/else anterior

   Efecto: PbConPunta? y PbTomaEncuentaVP? son ignorados. El símbolo
   nunca tiene punta y siempre usa el viewport, sin importar los parámetros.

   En TS: IndicadorResult.conPuntaActivo = false (siempre)
          IndicadorResult.usaViewportActivo = true (siempre)
   Los valores "intención" (conPunta param) se exponen por separado.


COMPONENTE REACT UI
--------------------
  LayoutElementUI:
  - Panel izquierdo: selector de registro GIS (3 mock records), sliders
    de parámetros (distXP, distYP, ancho, alto) y checkboxes.
  - Panel central: SVG 400×280 que muestra:
    · Página de layout (gris claro)
    · Viewport (rectángulo blanco con borde)
    · 3 puntos GIS (rojo/azul/verde) con labels
    · Línea indicadora (trazos) desde punto hasta style box
    · Style box (caja amarilla punteada) centrada en el endpoint
    · Arrowhead semitransparente cuando conPunta=true (demo de "intención")
    · Label "derecho" / "izquierdo" en el style box
  - Panel derecho:
    · Botones guardar/obtener: demuestra el ciclo de serialización
      ElementRef y recuperación desde dataset simulado
    · Demo transformaCoordenada: muestra canvas vs viewport coords
    · Tabla de atributos compartidos con defaults
