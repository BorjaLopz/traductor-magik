── QUÉ HACE ────────────────────────────────────────────────────────────────────

Lanza el proceso de centralización de plano en background con:
  1. Guard de instancia única — si ya hay proceso activo, devuelve false.
  2. UI opcional de interrupción — frame con label de progreso y botón kill.
  3. Proceso en background — fork a background_priority.
  4. Thread nombrado para monitorización de finalización.

Devuelve TRUE si lanzó correctamente, FALSE si ya había un proceso activo.

── GUARD DE INSTANCIA ÚNICA ────────────────────────────────────────────────────

  Magik: _if .thread _isnt _unset _then _return _false _endif
  TS:    if (this.thread !== null) return false;

  Garantiza que solo hay un proceso de centralización activo.
  Al completar (normal o abortado), this.thread se pone a null.

── PROCESO BACKGROUND ──────────────────────────────────────────────────────────

  Magik:
    plot_proc << _proc(owner) owner.int!do_plot() _endproc
    .thread << plot_proc.fork_at(_thisthread.background_priority, _self)
    .thread.set_name("centralizado_planos")

  TS:
    this.thread = Promise.resolve()
      .then(() => this.intDoPlot(signal))
      .then(...)    // done handler
      .catch(...)   // abort/error handler

  Promise.resolve().then() diferiere la ejecución al siguiente microtask,
  equivalente funcional al fork en background priority de Magik.

── CANCELACIÓN ─────────────────────────────────────────────────────────────────

  Magik: button_item con :kill||() llama _self.kill() que mata el thread.
  TS:    AbortController.abort() → signal.aborted = true → intDoPlot lanza AbortError.

  El signal se pasa a intDoPlot() que debe chequear signal.aborted en cada paso.
  Patrón: if (signal.aborted) throw new DOMException('...', 'AbortError');

── int!do_plot() ────────────────────────────────────────────────────────────────

  Magik: owner.int!do_plot() — método interno (! = internal en convención Magik)
  TS:    protected async intDoPlot(signal: AbortSignal): Promise<void>

  Sobreescribir en subclase para implementar la centralización real.
  El stub en la demo simula 6 pasos con delays de 800ms cada uno.

── UI — FRAME DE INTERRUPCIÓN ───────────────────────────────────────────────────

  Cuando enableInterrupt=true:
    - Aparece div posicionado (position:fixed si pos definido, relative si no).
    - Título del frame: "Centralizando el plano".
    - Label actualizado en cada paso del proceso (onStatusChange callback).
    - Botón "Interrumpir Centralización" → engine.kill().
    - Desaparece al completar o abortar.

  Cuando enableInterrupt=false:
    - Sin frame visible. Solo estado interno en statusBox.

── FLUJO DE USO ────────────────────────────────────────────────────────────────

  const engine = new LayoutPlotEngine();
  engine.onStatusChange = (status) => setStatus(status);  // conectar a React

  // Lanzar sin UI de interrupción:
  const ok = engine.centralizaLaunch();               // → true (lanzado)
  const ok2 = engine.centralizaLaunch();              // → false (ya activo, guard)

  // Lanzar con frame de interrupción posicionado:
  engine.centralizaLaunch(true, { x: 80, y: 120 });   // → true + frame visible

  // Interrumpir:
  engine.kill();                                       // → AbortError → phase='aborted'

  // Subclase para implementación real:
  class MyPlotEngine extends LayoutPlotEngine {
    protected async intDoPlot(signal: AbortSignal): Promise<void> {
      // lógica real de centralización...
      if (signal.aborted) throw new DOMException('', 'AbortError');
    }
  }
