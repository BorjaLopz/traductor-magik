=============================================================================
PROPÓSITO
=============================================================================
Plugin de series de planos. Gestiona la generación de documentos de layout
en serie (one page per frame/area). Sus responsabilidades:
  1. Detectar el tipo de plano activo (ruta/compa/esquematico/trayectoria/…)
  2. Leer la configuración (ace_name, display_style, style_group) desde planos_config.xml
  3. Propagar sectors_buffer a todos los viewports del documento
  4. Coordinar layout_series_engine.update_document (hilo separado en Magik)
  5. Responder al databus SW (:post_render_sets) dibujando áreas de ruta

=============================================================================
DECISIONES DE DISEÑO
=============================================================================

Shared state como módulo-level variables:
  En Magik son define_shared_variable en la clase (singleton de hecho).
  En TS son variables de módulo. Se exponen via LayoutSeriesPluginState
  para permitir reset en tests sin recrear la clase.

xmlLoader como inyección de dependencia:
  El original llama smallworld_product.get_data_file("planos_config.xml").
  En TS se inyecta una función (tipo: TipoPlano) => ConfigPlano que en
  producción lee el fichero y en tests usa el MOCK_XML_CONFIG.

int!make_document como async:
  El método de hilo Magik se convierte a async/await. layout_series_engine
  es un motor externo no migrado; el cuerpo deja el hook onProgress para
  integración futura.

agrega_particulares y dialogs SW:
  Dependen de la infraestructura de dialogs Smallworld (layout_designer,
  layout_manager, etc.) que no existe en TS. No se migran como métodos
  autónomos; la lógica de negocio (añadir elementos a páginas) se delegará
  al componente de layout React cuando se integre.
