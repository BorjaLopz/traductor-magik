1. PROPÓSITO
────────────
Orquestador del plano de Desmontaje de Caja de Distribución (CD).
Genera una página de layout compuesta por tres elementos colocados en
posiciones fijas (en unidades de layout, no en coordenadas GIS):

  ┌─────────────────────────────────────────────────────────────────────┐
  │  Marco (c_marco) — todo el plano, bounds (0,0) → (1,1)            │
  │                                                                     │
  │  ┌────────────────────────┐  ┌────────────────────────────────────┐ │
  │  │ Sello                  │  │  Viewport (viewport_layout)        │ │
  │  │ c_sello_proyecto_      │  │  bounds (2540,270) → (6600,2920)  │ │
  │  │ canalizacion           │  │  Vinculado al mapa GIS activo      │ │
  │  │ (420,0) → (3600,2920)  │  │                                    │ │
  │  └────────────────────────┘  └────────────────────────────────────┘ │
  └─────────────────────────────────────────────────────────────────────┘

En Smallworld este plano se insertaba en el Layout Designer y el viewport
se configuraba a partir del estado actual del mapa abierto (MapView).
En TypeScript todo es async y se obtiene mediante IPlanoService (mock).


2. QUÉ SE HA TRANSCRITO DEL CÓDIGO MAGIK
─────────────────────────────────────────

2.1  def_slotted_exemplar → clase PlanoDesmontajeCd
  Magik: hereda de :layout_element y :viewport_layout_mixin.
  Slot: :app (referencia a smallworld_product.pni_application()).
  TypeScript: constructor recibe IPlanoService (reemplaza toda la app PNI).

2.2  new() / init() → constructor
  Magik: new() clona + init() asigna .app.
  TypeScript: constructor con inyección de servicio. Sin clon necesario.

2.3  genera_plano() → async generaPlano(): Promise<LayoutPage | null>
  Magik:
    1. start_layout_designer() → si null: _return
    2. LoPagina.elements.size > 0 → LoPagina.elements.empty()
    3. _self.marco(LoPagina)
    4. _self.sello(LoPagina)
    5. _self.mapa(LoPagina)
  TypeScript:
    1. getLayoutPage() → null → return null
    2. pagina.elements = []
    3. push(crearMarco()) + push(crearSello()) + push(await crearMapa())

2.4  marco(LoPagina) → crearMarco(): MarcoConfig
  Magik:
    c_marco.new_with(:bounds, bounding_box.new(0,0,1,1))
    LoMarco.Largo = 3
    LoMarco.Alto  = 1
    LoMarco.set_fill_colour(_unset)  → sin relleno
  TypeScript: retorna MarcoConfig { bounds:(0,0,1,1), largo:3, alto:1, fillColor:null }
  NOTA: bounds (0,0,1,1) es el espacio normalizado del marco completo de la hoja.

2.5  sello(LoPagina) → crearSello(): SelloConfig
  Magik:
    c_sello_proyecto_canalizacion.new_with(:bounds, bounding_box.new(420, 0, 3600, 2920))
    LoSello.Inicializa()
  TypeScript: retorna SelloConfig con bounds y inicializado=true.
  NOTA: c_sello_proyecto_canalizacion es otra clase Magik (no migrada aquí).
        En TypeScript se modela como stub con su bounding box y flag de inicialización.

2.6  mapa(LoPagina) → async crearMapa(): Promise<ViewportConfig>
  Es el método más complejo. Lógica exacta transcrita:

  a) Crea viewport_layout con bounds (2540, 270, 6600, 2920).

  b) _if LoViewportLayout.mapped? _is false (siempre false en init):
     → entra en bloque de configuración.

  c) LoViewportBounds = bounds.new_enlarging(0.10)
     → TypeScript: enlargeBBox(vpBounds, 0.10)
     → amplía bbox un 10% en cada dirección.

  d) Cálculo de escala (lógica de bifurcación):
     - Si LoViewAngle.abs > 0.1°:
         LoViewScale = LoMapView.view_scale   (escala del mapa tal como está)
     - Si no (sin rotación significativa):
         LoViewScale = min(viewBounds.width / vpBounds.width,
                          viewBounds.height / vpBounds.height)
                       * app_cs.unit_factor
     → TypeScript: Math.min(viewW/vpW, viewH/vpH) * unitFactor

  e) Asignación de propiedades al viewport:
     soc_name         ← spatial_object_controller.name
     centre           ← LoViewBounds.centre  [midpoint del bbox de vista]
     view_scale       ← LoViewScale calculado
     view_angle       ← LoViewAngle (grados)
     ace_name         ← LoMapView.ace_name
     draw_scale       ← 1.0  (fijo)
     world            ← LoMapView.world

  f) Búsqueda del estilo de visualización:
     Magik:
       _for item _over display_styles.fast_elements()
         _if display_style_name _is item.scale_id
           display_style = item.name
       LoViewportLayout.display_style << display_style.default(first.name)
     TypeScript:
       displayStyles.find(s => s.scaleId === currentStyleName)?.name
       ?? displayStyles[0]?.name  ← fallback al primer estilo

  g) projection        ← LoMapView.current_view_parameters().coordinate_system
     coordinate_system ← LoMapView.application.coordinate_system

6. LÓGICA DE ESCALA DEL VIEWPORT
──────────────────────────────────
  El cálculo es la parte más relevante del método mapa():

  Con rotación (ángulo > 0.1°):
    → Se usa la escala actual del mapa sin modificar.
    → Razón: con rotación, el ratio de bounds no es válido directamente.

  Sin rotación (ángulo ≤ 0.1°):
    → escala = min(anchoVista / anchoViewport, altoVista / altoViewport)
               × unitFactor (conversión de unidades del SRC)
    → El min asegura que TODO el contenido de la vista cabe en el viewport.
    → unitFactor ajusta la escala al sistema de coordenadas (ej.: UTM → metros).

  Este cálculo determina a qué escala cartográfica se imprimirá el mapa
  dentro del viewport del plano.
