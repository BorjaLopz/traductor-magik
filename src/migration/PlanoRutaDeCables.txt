── QUÉ HACE ────────────────────────────────────────────────────────────────────

Es el compositor principal del plano "Ruta de cables": un objeto de tipo
layout_element (elemento de plano imprimible) que sabe cómo construir la
página de layout con todos sus componentes.

Ensamble de la página (contenido real del plano):

  ┌─────────────────────────────────────────────────────────────┐
  │  Marco (c_marco)                                            │
  │  6" × 3"  (1500 × 750 u.p.)  sin relleno                   │  ← borde/marco general
  │  ┌─────────────────────────────┐   ┌─────────────────────┐  │
  │  │   Sello CTL-EDO             │   │  Sello PEP          │  │
  │  │   c_sello_estandar_ctl_edo  │   │  c_pep              │  │
  │  │   (250,250)→(3000,2990)     │   │  (450,500)→(1330,   │  │
  │  │   2750 × 2740 u.p.          │   │   1410)             │  │
  │  │   ≈ 11" × 10.96"            │   │  880 × 910 u.p.     │  │
  │  │   [clase [10] SelloEstandar]│   │  ≈ 3.52" × 3.64"   │  │
  │  └─────────────────────────────┘   └─────────────────────┘  │
  └─────────────────────────────────────────────────────────────┘

  Factor de escala: LnPulgada = 250 u.p./pulgada

Contexto técnico:
  Un "plano ruta de cables" es el documento técnico oficial que muestra el
  trazado de la infraestructura de telecomunicaciones (cables de fibra óptica,
  cobre, etc.) a lo largo de un corredor o ruta. Se genera en el Layout
  Designer de Smallworld GIS y contiene: marco, sello PEP (datos del proyecto),
  sello de control de estado y la vista georreferenciada del mapa (viewport).

── NOTA SOBRE EL CÓDIGO ORIGINAL ───────────────────────────────────────────────

  El cuerpo de genera_plano() está COMPLETAMENTE COMENTADO en el Magik original.
  Solo los métodos new(), init() y defined_attributes() tienen código activo.

  La implementación TypeScript de generaPlano() RECONSTRUYE la intención a partir
  del código comentado en el .magik, incluyendo tipos, coordenadas y nombres
  de los elementos de página. Este es el principal valor de la migración.

── RELACIÓN CON OTRAS MIGRACIONES ──────────────────────────────────────────────

  [10] SelloEstandar → CSelloEstandarCtlEdo es el tipo de sello que esta clase
       usa como tercer elemento de página. En [10] es un stub; en [20] se
       referencia por tipo e interfaz sin importar directamente.

  [15-17] familia c_sello_notas_sct → mismo patrón de compositor de plano,
          donde el "sello" es un elemento ensamblado por una clase compositora.

── TIPOS CLAVE INTRODUCIDOS ────────────────────────────────────────────────────

  BoundingBox          ≡ bounding_box.new(x1,y1,x2,y2)
  LayoutPage           ≡ layout_page con elements[]
  LayoutDocument       ≡ layout_document (name + tipo + página)
  CMarcoConfig         ≡ c_marco con Largo/Alto/fillColor
  CPepConfig           ≡ c_pep
  CSelloEstandarCtlEdoConfig ≡ c_sello_estandar_ctl_edo
  AppService           ≡ smallworld_product.pni_application()

── LO QUE NO SE TRANSCRIBIÓ ────────────────────────────────────────────────────

- define_shared_constant(:allowed_on_menu?, _false, :public)
  → Metadato Smallworld. Sin equivalente TS.

- viewport_layout_mixin (herencia múltiple Magik)
  → En TS se refleja solo como atributo descriptor (viewport en defined_attributes).
    No hay clase base TS con capacidades de viewport.

- layout_element (herencia base de Smallworld)
  → Sus atributos (bounds, visible) se incluyen en definedAttributes() como stub.

- _pragma(classify_level=restricted, usage={redefinable})
  → Metadatos de accesibilidad Smallworld. Sin equivalente TS.

- LoLayoutDesigner.plugin(:layout_manager).current_document
  → Integración con el Layout Designer de Smallworld. En TS se omite la capa
    de integración con el framework GIS y se devuelve el LayoutDocument directamente.

- LoPagina.elements.empty() (limpiar página antes de regenerar)
  → No aplicable en TS ya que generaPlano() siempre crea una página nueva.

── FLUJO DE USO ────────────────────────────────────────────────────────────────

  // Solo lógica:
  const plano = CPlanoRutaDeCables.new();
  const doc = plano.generaPlano();

  doc.name                    // → 'Plano ruta de cables'
  doc.userTipoPlano           // → 'ruta_cables'
  doc.currentPage.elements    // → [CMarcoConfig, CPepConfig, CSelloEstandarCtlEdoConfig]

  const marco = doc.currentPage.elements[0] as CMarcoConfig;
  marco.largo                 // → 6  (pulgadas)
  marco.alto                  // → 3  (pulgadas)
  marco.fillColor             // → null  (set_fill_colour(_unset))

  // Atributos del layout element:
  CPlanoRutaDeCables.definedAttributes()
  // → [{ name:'bounds', type:'bounding_box', ... },
  //    { name:'visible', type:'boolean', ... },
  //    { name:'viewport', type:'viewport', description:'Vista GIS...' }]
