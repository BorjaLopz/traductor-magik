PROPÓSITO
---------
Plugin del framework GUI de Smallworld que gestiona la vista previa interactiva
de símbolos GIS del catálogo sigc (sigc_style_view). Sus responsabilidades son:

  · Inicializar y mantener la referencia a sigc_style_view (BD de estilos GIS)
  · Controlar el acceso de escritura a esa BD (modo :write / :readonly)
  · Registrar y habilitar/deshabilitar 4 acciones según permisos (sw_action)
  · Abrir un diálogo de vista previa (c_preview_symbol_dialog) con catálogo de símbolos
  · Publicar el símbolo seleccionado en el databus (:symbol_name)
  · Consolidar (merge) o propagar (post) cambios en la BD de estilos


SLOT MIGRADO
-------------
  .sigc_style_view → _sigcStyleView: SigcStyleView | null
    Referencia a la vista de estilos GIS (gis_program_manager.databases[:sigc_style_view]).
    Se inicializa en init(): si el DB está registrado se usa esa instancia;
    si no, se llama user:abre_style_sigc() como fallback.

  Propiedades (def_property equivalentes):
    x_offset → xOffset: number (default 0)  Desplazamiento X del diálogo
    y_offset → yOffset: number (default 0)  Desplazamiento Y del diálogo

  Constante compartida (define_shared_constant):
    databusProsumerDataTypes = ['symbol_name']
    Equivale a: define_shared_constant(:databus_producer_data_types, {:symbol_name}, :public)

DATABUS PATTERN
----------------
Magik define_shared_constant(:databus_producer_data_types, {:symbol_name}, :public)
indica que este plugin "publica" el valor :symbol_name en el databus del framework.
En TypeScript:
  static readonly databusProsumerDataTypes = ['symbol_name'] as const
El símbolo seleccionado en el catálogo representa el valor publicado.
En producción, esto notificaría a otros componentes suscritos al databus qué símbolo
está seleccionado actualmente.


SIGC_STYLE_VIEW — CONTROL DE VERSIONES
----------------------------------------
La BD sigc_style_view funciona como una BD versionada de Smallworld:
  :write    → el usuario tiene acceso en escritura, puede modificar estilos
  :readonly → solo lectura, los botones de escritura se deshabilitan
  current_writer → identifica qué usuario tiene el "lock" de escritura
  merge()   → consolida cambios locales hacia la copia base (como git merge)
  post()    → propaga cambios hacia otras vistas (como git push)

En la UI se puede simular cualquier combinación de estos estados para verificar
el comportamiento de manage_actions().


DIFERENCIAS RESPECTO AL MAGIK ORIGINAL
----------------------------------------
· :plugin (framework Smallworld) no está migrado. Las funcionalidades del plugin
  (registro, activación, gestión de framework) se simulan directamente en la clase.

· sw_action con :image → en TS los botones no tienen icono de módulo; el estado
  enabled/disabled se representa con color y badge ON/OFF.

· get_dialog / cache_dialog → patrón de caché de diálogos de Smallworld.
  En TS el modal es un único componente React; no hay caché explícita.

· activate_relative_to(title, top_frame, x, y) → en TS el modal se centra en
  la ventana del navegador; x_offset/y_offset se muestran como metadato informativo.

· gis_program_manager no existe en TS. Se reemplaza por createMockSigcStyleView()
  que devuelve una instancia configurable desde la UI.

· smallworld_product.application_definition(:sigc_style_symbol_editor).start/restart
  → stub que muestra mensaje de confirmación; no existe la aplicación real.

· build_gui(container) / build_embedded_gui(container) → toda la UI se representa
  en PreviewSymbolPluginUI como componente React autocontenido.

· El componente UI añade:
  - Controles interactivos para simular el estado de sigc_style_view
  - Indicador visual del resultado de manage_actions()
  - Badges ON/OFF en cada botón de acción
  - Modal con catálogo de 9 símbolos clicables (c_preview_symbol_dialog simulado)
  - Panel de mensajes para show_message / condition.raise
