DESCRIPCIÓN GENERAL
-------------------
Sello de pie para diagrama de empalmes. En Magik hereda de
c_sello_estandar_ctl_edo mediante def_slotted_exemplar con slots vacíos
(no añade slots nuevos). En TypeScript se modela como componente React
funcional con estado local; la herencia se simula con llamadas equivalentes
a los métodos del padre comentadas en el código.

Añade una tabla extra al sello base (tbl_colonia_cp) y un método espacial
relevante: delegacion_municipio(), que determina el municipio del sello
mediante queries GIS de tipo within e interacts sobre geometrías reales.


SLOTS MIGRADOS
--------------
No hay slots propios en este exemplar.
Los datos heredados de c_sello_estandar_ctl_edo se modelan como PlDatos.

3. delegacion_municipio() — MÉTODO ESPACIAL PRINCIPAL
   Magik: lógica con tres ramas según tipo_diseno del diseño activo:

   Rama :principales / :trabajo / :enlace:
     1. LoV.collection(:building) → buildings
     2. predicate.within(:location, central.user!_limite) → booleanWithin
     3. Lonodo = tabla.select(pred).an_element() → primer building dentro
     4. cached_dataset(:landbase).collection(:user!_municipio) → municipios
     5. predicate.interacts(:user!_limite, Lonodo.location) → booleanIntersects
     6. if LoSel.size = 1 → LoMun.nombre_telmex + ", " + LoMun.estado

   Rama :secundaria:
     1. Busca CD (mit_terminal_enclosure) within central.user!_limite
     2. Si CD existe: municipio que interacta con CD.location
        Formato: nombre + "," + estado (sin espacio, como en el original)
     3. Si no hay CD: fallback a building (mismo algoritmo que :principales)

   TypeScript: función async delegacionMunicipio() con:
     - turf.booleanWithin(point, polygon)  ↔  predicate.within(:location, LoArea)
     - turf.booleanIntersects(poly, point) ↔  predicate.interacts(:user!_limite, location)
     - matches.length === 1               ↔  LoSel.size = 1
     La función recibe collections como parámetros en vez de acceder
     a globals (mit_manager, gis_program_manager).

4. etiqueta_celdas()
   Magik: _super.etiqueta_celdas() + asigna_texto_celda para 2 celdas:
     - tbl_colonia_cp, fila 1, col 1 → "COLONIA: "  (fontSize 35, top_left)
     - tbl_colonia_cp, fila 2, col 1 → "C.P.: "     (fontSize 35, top_left)
   TypeScript: etiquetas hardcodeadas en la primera columna de TblColoniaCp.

5. llena_datos_celdas()
   Magik: solo llama _super.llena_datos_celdas(), sin lógica propia.
   TypeScript: los datos de colonia y cp se muestran directamente en
   la segunda columna de TblColoniaCp desde PlDatos.

6. obten_registros()
   Magik: _super.obten_registros() + asigna_distrito(_false) + rellena:
     - .pl_datos[:colonia] ← .o_distrito.nombre_colonia
     - .pl_datos[:cp]      ← .o_distrito.codigo_postal

   no tiene equivalente directo — indica que no se recalcula el área del

7. valor_casilla_central()
   Magik: _return .pl_datos[:clave_ctl] + " - " + .o_proyecto.numero_distrito
   TypeScript: función valorCasillaCentral(datos: PlDatos): string.
   Formato resultado: "NOR-01 - D-042"


LÓGICA ESPACIAL — DETALLE
--------------------------
El método delegacion_municipio() es el único con lógica espacial real.
Patron Magik → Turf.js:

  predicate.within(:location, LoArea)
    → turf.booleanWithin(elemento.location [Point], centralLimite [Polygon])
    → true si el Point está completamente dentro del Polygon

  predicate.interacts(:user!_limite, Lonodo.location)
    → turf.booleanIntersects(municipio.user_limite [Polygon], nodo.location [Point])
    → true si hay cualquier intersección geométrica

  tabla.select(pred).an_element()
    → coleccion.find(el => predicado(el))   (primer elemento que cumple)

  LoSel.size = 1
    → matches.length === 1   (exactamente un municipio coincide)

La distinción de formato entre ramas es exacta al original:
  - :principales/:trabajo/:enlace → "NOMBRE, ESTADO"  (coma + espacio)
  - :secundaria con CD            → "NOMBRE,ESTADO"   (solo coma, sin espacio)
  Esta diferencia existe en el Magik original y se ha preservado fielmente.

LO QUE NO SE HA MIGRADO
------------------------
- La herencia real de c_sello_estandar_ctl_edo no existe en TypeScript;
  los campos heredados (clave_ctl, nombre_central, numero_distrito) se
  modelan directamente en PlDatos.
- swg_dsn_admin_engine.active_design: objeto global Magik; aquí se pasa
  como parámetro ActiveDesign para evitar globals en TypeScript.
- mit_manager.modelit_dataset y gis_program_manager.cached_dataset:
  accesores globales GIS; reemplazados por arrays mock pasados como parámetros.
- asigna_distrito(_false): el segundo parámetro _false que inhibe el
  recálculo del área no tiene representación en TypeScript.
- El posicionamiento en plano imprimible (coordinate.new, ln_desp_x/y)
  requeriría integración con LayoutPlotEngine [11].
