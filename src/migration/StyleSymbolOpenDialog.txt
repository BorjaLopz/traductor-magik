── QUÉ HACE ────────────────────────────────────────────────────────────────────

Renderiza la previsualización de un símbolo de punto GIS en un canvas de
un diálogo de selección de símbolos (style_symbol_open_dialog).

Contexto de uso en Smallworld:
  El diálogo permite al usuario elegir un símbolo de una lista (e.g. PUNTO_NODO,
  EMPALME, CÁMARA...). Cada vez que el usuario selecciona uno, draw_preview
  lo dibuja en el área de previsualización del diálogo.

Flujo del método original:
  1. Limpia el canvas de previsualización.
  2. Si el nombre de símbolo no es nulo (symbol_name _isnt _unset):
     a. Obtiene la tabla de estilos de puntos GIS:
        - Si el owner tiene sigc_style_view → usa esa vista (proyecto específico)
        - Si no → usa gis_program_manager.style_view (vista global del programa)
     b. Crea un registro detached de la tabla (new_detached_record).
     c. Asigna el nombre del símbolo al registro.
     d. "Realiza" (carga/resuelve) el símbolo con realise().
     e. Si el símbolo tiene geometrías reales (actual_geoms _isnt _unset):
        → Dibuja una muestra con rotate=0, flipped=true, mirror=false.

── MÉTODO TRANSCRITO ───────────────────────────────────────────────────────────

Magik: style_symbol_open_dialog.draw_preview(symbol_name)
TS:    StyleSymbolOpenDialog.drawPreview(symbolName: string | null): void

  Magik                                       TypeScript
  ─────────────────────────────────────────   ──────────────────────────────────
  .preview_canvas.clear()                  →  ctx.clearRect(0, 0, w, h)
  symbol_name _isnt _unset                 →  symbolName !== null
  point_style_table.new_detached_record()  →  service.getSymbol(name)     ①
  sym.symbol_name << symbol_name           →  (dentro de getSymbol)       ①
  sym.realise(_unset, _unset)              →  (dentro de getSymbol)       ①
  sym.actual_geoms _isnt _unset            →  sym.hasActualGeoms === true
  sym.draw_sample(canvas, bounds, ...)     →  drawSample(ctx, bounds, ...) ②

  ① Los 3 pasos Magik (new_detached_record + asignar nombre + realise) se
    condensan en un único service.getSymbol(name): devuelve la definición
    completa o undefined si no existe / no se pudo realizar.

  ② drawSample() implementa los parámetros Magik en Canvas2D:
      :rotate 0.0     → ctx.rotate(0)  (sin efecto, fiel al original)
      :flipped? _true → ctx.scale(1, -1)  ← invierte eje Y
                         Razón: Smallworld usa Y-arriba (coords GIS proyectadas);
                         HTML Canvas usa Y-abajo. Con flipped=true el símbolo
                         se dibuja correctamente en el espacio de pantalla.
      :mirror? _false → sin ctx.scale(-1, 1)  (no hay inversión horizontal)

── ABSTRACCIÓN SymbolStyleService ──────────────────────────────────────────────

  El Magik original tiene dos fuentes para la tabla de estilos:

    FUENTE 1 (proyecto):
      .owner.responds_to?(:sigc_style_view)
      → .owner.sigc_style_view.collection(:sw_gis!gis_point_style)

    FUENTE 2 (global):
      gis_program_manager.style_view.collection(:sw_gis!gis_point_style)

  En TS se abstrae como SymbolStyleService (interfaz inyectable):

    getSymbol(name): SymbolDefinition | undefined
      ← new_detached_record() + sym.symbol_name + sym.realise()

    listSymbolNames(): string[]
      ← iteración sobre la colección (para el selector del demo)

  El componente acepta un service por props; si no se pasa, usa
  mockSymbolStyleService con 7 símbolos de prueba predefinidos.

── PARÁMETROS draw_sample (FIJOS en el Magik original) ────────────────────────

  :rotate   0.0    → sin rotación
  :flipped? _true  → eje Y invertido (GIS → pantalla)
  :mirror?  _false → sin inversión horizontal

  Estos valores están hardcodeados en el método Magik. En TS se recogen
  en DrawSampleParams y se guardan en la propiedad drawParams de la clase.

── LO QUE NO SE TRANSCRIBIÓ ────────────────────────────────────────────────────

- .owner.responds_to?(:sigc_style_view)
  → Introspección dinámica de Smallworld. En TS se resuelve en tiempo de
    construcción mediante la inyección del service correcto (proyecto vs global).

- point_style_table.new_detached_record()
  → Mecánica interna del ORM de Smallworld (registro no persistido).
    Sustituido por service.getSymbol() que devuelve directamente la definición.

- sym.realise(_unset, _unset)
  → Carga asíncrona de geometrías en Smallworld. En TS se asume que el service
    devuelve el símbolo ya "realizado" (datos completos). Si fuera una API REST
    real, getSymbol() sería async.

- _self.canvas_bounds
  → Bounds del canvas calculados por el diálogo Smallworld. En TS se lee
    directamente de HTMLCanvasElement.width / .height.

- Geometrías reales sw_gis!gis_point_style (vectores Smallworld)
  → No tienen equivalente directo. Se sustituyen por formas Canvas2D
    parametrizadas (circle, square, triangle, diamond, star, cross).

── FLUJO DE USO ────────────────────────────────────────────────────────────────

  // Sin mapa (solo lógica):
  const dialog = new StyleSymbolOpenDialog(myService);
  dialog.setCanvas(canvasElement);
  dialog.drawPreview('EMPALME');     // limpia + dibuja preview
  dialog.drawPreview(null);          // solo limpia

  // Con service personalizado:
  const dialog = new StyleSymbolOpenDialog({
    getSymbol: (name) => myProjectSymbols.find(s => s.symbolName === name),
    listSymbolNames: () => myProjectSymbols.map(s => s.symbolName),
  });

  // Componente demo React:
  <StyleSymbolOpenDialogUI />                        // usa mock service
  <StyleSymbolOpenDialogUI service={myService} />    // servicio real/proyecto
  <StyleSymbolOpenDialogUI canvasSize={160} />       // canvas 160×160
