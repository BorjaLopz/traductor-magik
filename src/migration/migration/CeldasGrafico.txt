SLOTS ORIGINALES (Magik)  ->  PROPIEDADES TS
--------------------------------------------
sNombre_Grafico   ->  sNombreGrafico : string | null
bVoltear_H        ->  bVoltearH      : boolean (flip horizontal, conservado)
bVoltear_V        ->  bVoltearV      : boolean (flip vertical, conservado)
nGrados           ->  nGrados        : number  (rotacion en grados)
bBordeSup         ->  bBordeSup      : boolean
bBordeInf         ->  bBordeInf      : boolean
bBordeIzq         ->  bBordeIzq      : boolean
bBordeDer         ->  bBordeDer      : boolean
sColorLinea       ->  sColorLinea    : string (color hex)
oArea (heredado)  ->  oArea          : Bounds {xmin, xmax, ymin, ymax}

METODOS MAGIK MIGRADOS
----------------------
1) bBorde_{Sup,Inf,Izq,Der}? / << RbValor
   Getters/setters de cada bandera de borde. En TS son simples propiedades
   publicas: leer/escribir `instancia.bBordeSup`, `instancia.bBordeInf`, etc.

2) color_linea / color_linea << RsColor
   Getter/setter del color. En TS es la propiedad `sColorLinea`.

3) new()
   Magik: `_clone.init()`. En TS lo cubrimos con el factory estatico
   `CeldasGrafico.create(area)` que tambien dispara `init()`.

4) init()
   Magik: pone `color_linea` a negro (rgb 0,0,0). En TS: asigna
   `this.sColorLinea = '#000000'` y retorna `this`.

5) init_with(props)
   Magik: copia bBordeDer/Inf/Izq/Sup desde el dict de propiedades. En TS,
   `initWith(props)` acepta el mismo set + color/nombre/flip/rotacion, y aplica
   solo los campos definidos para preservar los defaults.

6) serial_slots()
   Magik: anade al rope del padre las claves bBordeSup, bBordeInf, bBordeIzq,
   bBordeDer y ColorLinea. En TS `serialSlots()` devuelve un par
   `{ keys, values }` con las mismas claves (sin la herencia del padre, que
   no aplica fuera de Magik).

7) Despliega()  ** principal **
   Magik: si la bandera de un borde esta activa, construye un `coords_vector`
   con 2 vertices del rectangulo y llama `oVentana.draw_line_transform(...)`.
   Resultado: hasta 4 lineas dibujadas:
     - Sup: (Xmax, Ymax) -> (Xmin, Ymax)
     - Inf: (Xmin, Ymin) -> (Xmax, Ymin)
     - Izq: (Xmin, Ymax) -> (Xmin, Ymin)
     - Der: (Xmax, Ymin) -> (Xmax, Ymax)
   En TS `despliega()` devuelve `{ segments, style }`, donde `segments` es un
   array de `{x1,y1,x2,y2,borde}`. El renderizado se desacopla del calculo:
   el consumidor decide donde pintarlo (SVG, OpenLayers, canvas, ...).

EXTENSIONES TS QUE NO EXISTIAN EN MAGIK
---------------------------------------
- desplegarEnOpenLayers(source: VectorSource)
  Convierte cada segmento en un `ol/Feature` con un `ol/geom/LineString` y
  estilo `Stroke` (color + width). Equivale moderno a la llamada Magik
  `oVentana.draw_line_transform(LoEstiloLinea, LoCoordenada)`.

- desplegarComoGeoJson()
  Convierte cada segmento en un `Feature<LineString>` GeoJSON (via Turf),
  util si despues queremos calcular intersecciones, longitudes, buffers, etc.

- segmentToOlFeature(seg, style) y segmentToTurfLine(seg)
  Helpers puros que aislan la traduccion segmento -> Feature OL / Turf.

INTENCION
---------
La clase representa **una celda de un grafico tabular** (pensada para sellos
y leyendas). Cada celda conoce sus 4 bordes opcionales y sabe dibujarlos
sobre su area asignada. En el Magik original, los bordes se pintaban
directamente sobre la ventana. En la migracion TS aplicamos el patron
"calcula + retorna geometria" para que la misma clase sirva en:
  - una vista React (SVG) — preview en `CeldasGraficoUI`
  - una capa de mapa (OpenLayers VectorSource)
  - un pipeline de analisis espacial (Turf / GeoJSON)

COMPONENTE REACT (CeldasGraficoUI)
----------------------------------
Demo interactiva:
  - 4 checkboxes para activar/desactivar cada borde.
  - selector de color para `sColorLinea`.
  - render SVG con el `oArea` (rectangulo sombreado de referencia) y las
    lineas correspondientes a los bordes activos.
  - lista al pie con los bordes que se acaban de dibujar.

EQUIVALENCIAS RAPIDAS (Magik -> TS)
-----------------------------------
  _self.bBordeSup << _true        ->  instancia.bBordeSup = true
  _self.color_linea << "#ff0000"  ->  instancia.sColorLinea = "#ff0000"
  _self.Despliega()               ->  await instancia.despliega()
  oVentana.draw_line_transform(.) ->  instancia.desplegarEnOpenLayers(source)
  line_style.new_with_properties  ->  ol/style/Style + ol/style/Stroke

USO MINIMO (snippet)
--------------------
  import { CeldasGrafico } from './migration/CeldasGrafico';
  const celda = CeldasGrafico.create({ xmin: 0, xmax: 100, ymin: 0, ymax: 50 });
  await celda.initWith({ bBordeSup: true, bBordeInf: true, sColorLinea: '#1f6feb' });
  const { segments, style } = await celda.despliega();

  // ... o directamente sobre OpenLayers:
  const source = new VectorSource();
  await celda.desplegarEnOpenLayers(source);

NOTAS Y SUPUESTOS
-----------------
- `oArea` se hereda en Magik de `c_elemento_grafico`. Aqui lo declaramos
  directamente en `CeldasGrafico` porque no tenemos aun la migracion del
  padre. Si en el futuro se crea `c_elemento_grafico`, lo natural es que
  `CeldasGrafico` extienda esa clase y reciba `oArea` por composicion.
- Los slots `bVoltear_H`, `bVoltear_V` y `nGrados` se mantienen como
  propiedades pero `Despliega()` no los aplica todavia (en el Magik
  original tampoco se aplican dentro de este metodo concreto; pertenecen
  al pipeline padre).
- `sNombreGrafico` se conserva por compatibilidad de slot.
- Las llamadas async no son estrictamente necesarias para el calculo, pero
  se mantienen para alinear la API con el resto de migraciones del proyecto
  (todas usan `await` en `despliega()`/`initWith()`).
